# 京东 AI 短视频流程

一个商品一个目录：`products/<slug>/商品.md` 加上该商品的参考图和视频。`商品.md` 是唯一的进度记录，每完成一步就更新它的对应章节和「状态」。

制作方法以 `docs/video-prompt-strategy.md` 为准，写提示词前先读它。发布要求见 `README.md` 的「内容制作要点」与「待核实与统一的事项」。

## 工具

| 命令 | 用途 |
| --- | --- |
| `workflow/bin/jd-new <slug> [sku] [url] [title]` | 从模板建商品目录 |
| `workflow/bin/jd-account list` / `open <name>` | 列出账号；用独立 Chrome 配置打开某个账号 |
| `workflow/bin/jd-check <video>` | 用 ffprobe 检查比例、分辨率、时长、音轨 |
| `workflow/bin/jd-stats` | 汇总所有商品「发布后数据」的最后一行 |

账号定义在 `workflow/accounts.conf`。浏览器操作用 Claude in Chrome 工具；每个账号是单独的 Chrome 进程，先用 `list_connected_browsers` / `select_browser` 选中对应账号的浏览器。

## 步骤

1. **选品与事实卡**：打开商品页，核对当前选中的款式、颜色、尺寸，填写事实卡。只写商品页明确的资料并注明来源；评论不是实测证据；价格和佣金只记录为观察值。下载单商品清晰图存为 `reference.jpg`，记录来源。
2. **内容定位与提示词**：按策略文档选 2–3 个有依据的信息点，用单镜头模板写提示词和旁白，写进 `商品.md`。先给用户看，确认后再生成。
3. **生成**：用 `jd-account open` 打开豆包账号。用 `read_page` 先观察页面实际结构，不假设按钮位置。上传参考图，核实图片是否真的绑定到首帧槽并记录。**点击生成前先征得用户同意，因为会消耗额度。**
4. **下载与技术检查**：视频存到商品目录，命名 `v<N>.mp4`，运行 `jd-check`，把结果写进实验记录。
5. **验收**：抽帧检查商品匹配与时间连续性，记录具体时间点。完整播放和听检必须由用户完成，没完成就标「待核查」，不能标「通过」。同一问题连续出现两次，改变制作方式，不要只加禁止词。
6. **发布草稿**：写标题、文案，选封面，勾选发布前检查。
7. **发布辅助**：用 `jd-account open` 打开京东账号，可以帮忙填写标题、上传素材，内容类型中**必须勾选【AI创作声明】**（未勾选会被收回发文权限），但**最终提交必须由用户自己点击**。提交后记录平台内容 ID 或「待核对」，之后跟进审核结果。
8. **发布后数据**：用户提供或在后台读到的播放、点击、订单、预估佣金，按日期追加到「发布后数据」表，填累计值，不要覆盖旧行。运行 `jd-stats` 汇总。分析时先看每条视频的平均点击（平台是否给流量），再看成交率和每单佣金；样本少于 10 条时只说趋势，不下结论。预估佣金不等于结算收入。

## 规则

- 不编造卖点、参数、体验或效果；资料缺失就写明缺口。
- 不处理验证码、扫码登录，遇到时交给用户。
- 不去水印、不批量套用模板、不养号、不绕过平台限制。
- 不把凭据、Cookie 写进仓库；Chrome 配置在 `~/.local/share/jd-affiliate/chrome/`，不在仓库内。
- 结论只用「通过 / 需修改 / 待核查」，写明证据和未完成的检查。
