# 京东 AI 短视频带货与佣金实战 软件开发计划

编写日期：2026-10-24。状态：Tauri 技术验证中。第一阶段平台：macOS。

选型决策：先验证 Tauri 2；若关键网页路径不满足要求，回退 Electron。验证代码位于 `desktop/`，结果与回退标准见 [平台验证记录](platform-validation.md)。

开发进度：账号元数据层已引入 SQLite、旧数据事务迁移及可恢复归档；商品工作区已实现录入、编辑、搜索、CSV 预览及整批事务导入；脚本工作区已接入三类本地模板、正文编辑及不可变版本历史，保存商品快照并检测资料变更，数据库升级前保留备份。当前脚本组装不调用 AI，候选标题、素材及任务队列尚待开发。桌面控制权限仍阻止原生 UI 实测，M0 未验收，尚不能据此确定最终技术栈。

界面进度：已按原软件参考整合工作台布局、账号多选归档与运行日志；浏览器演示模式已完成关键交互检查，不代替原生平台集成验收。

## 1. 产品目标与当前基础

开发一款 macOS 桌面工作台，让运营人员集中管理京东与豆包账号，将商品资料、脚本、视频、封面、标题和发布记录串成可追踪的工作流，减少重复录入和人工切换。

现有输入为 `software.jpg`、两份培训课件及 `realdata.mp4`。截图是功能参考，不能作为现有软件源码或已验证接口；佣金录屏只作为业务指标样例，不作为软件性能或收益验收标准。

第一阶段成功标准：用户在 Mac 上完成一个真实商品的导入、脚本准备、豆包视频生成或人工导入、素材检查、京东发布辅助和结果记录，并能在中断后继续处理。

## 2. 第一阶段范围 macOS MVP

首版优先 Apple Silicon，以 macOS 14 及以上为支持基线，使用独立 WebKit 数据存储隔离账号；Intel 安装包在第二阶段补齐。先通过签名并公证的 DMG 直接分发。

| 模块 | 首版交付 | 验收要点 |
| --- | --- | --- |
| 账号管理 | 新增、命名、打开、切换、退出和删除京东或豆包账号；独立会话目录 | 两个同平台账号互不串号，重启后会话可恢复；失效状态有明确提示 |
| 商品工作区 | 手动录入或 CSV 导入商品链接、SKU、标题、图片与卖点；搜索、筛选、编辑 | 重复导入可识别；缺失必填项有逐行提示；佣金等字段注明来源与更新时间 |
| 提示词与脚本 | 服装、大物件、通用品类模板；变量替换、预览、版本保存 | 不同 SKU 的资料互不覆盖；生成前可人工修改并确认 |
| 豆包操作 | 打开指定账号、辅助填写提示词、跟踪可识别的生成状态、接收素材 | 只对实测成功的操作启用自动化；未支持环节可人工完成并导入 |
| 素材库 | 视频与封面导入、下载、预览、关联 SKU；记录来源与版本 | 下载完整后才标记完成；标题、视频与封面始终关联同一商品版本 |
| 标题生成 | 保存候选标题、人工选择与编辑、写回商品记录 | 标题不覆盖其他商品；模板规则可配置且可追溯 |
| 任务中心 | 持久队列、暂停、取消、重试、运行日志和人工接管 | 重启不丢任务；同一账号同一时刻只执行一个自动化任务 |
| 京东发布辅助 | 打开对应创作者账号，辅助上传视频、填写标题与挂品，展示最终检查 | MVP 最终提交由用户操作；记录提交结果或人工核对状态，不能将点击成功当作上线 |
| 数据概览 | 展示素材数量、任务完成率、失败原因、待发布数量；支持手动录入佣金数据 | 样例数据与用户数据分开，预估、结算及到账口径分开 |
| 设置与诊断 | 下载目录、并发上限、日志导出、存储占用、本地备份 | 导出诊断不含 Cookie、令牌或密码；备份恢复有清晰范围 |

首版不包含：自动养号、验证码处理、账号等级付费升级、绕过平台限制、批量无人值守最终发布、自动去水印、收益预测、云端账号同步、收费授权系统和移动端自动化。截图中的 `0/4` 不作为固定额度规则，只有实际可读取或用户配置的限额才展示。

## 3. 用户操作路径与界面

主导航采用“工作台、账号、商品、任务、素材、发布记录、设置”。商品详情展示当前阶段、所用账号、脚本版本、素材和最近失败原因。

主流程：

1. 添加豆包与京东账号，在真实网页中由用户登录。
2. 导入一个商品，确认 SKU、图片和事实卖点。
3. 选择模板并修改脚本，选择执行账号。
4. 启动生成任务，等待完成或按提示接管；也可导入已生成素材。
5. 预览视频与封面，选择标题，完成货品一致性及内容检查。
6. 打开京东发布页，辅助填写，展示最终内容与挂品清单。
7. 用户提交，软件保存平台内容 ID 或待核对记录，后续更新审核状态。

管理界面参考截图中的列表与日志组织，第一轮验证使用独立账号网页窗口，避免将不稳定的子 WebView API 作为前提；嵌入式布局在验证后决定。最小窗口以 1280×800 为设计起点，小尺寸下折叠日志与次要列。

## 4. 技术方案

以下为拟定方案，M0 验证后固定依赖版本并提交锁文件。

| 层级 | 选择 | 用途 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 + Rust，Electron 作为回退 | 桌面生命周期、网页会话、下载与本地文件访问 |
| 本地界面 | React + Vite | 账号表格、商品详情、素材预览和任务状态 |
| 网页容器 | 稳定的 WebviewWindow API，macOS 使用 WKWebView | 每个账号使用稳定 UUID 对应的 dataStoreIdentifier，验证持久化与隔离 |
| 本地存储 | SQLite + rusqlite，锁定版本见 Cargo.lock | 已落地账号、商品与脚本；后续扩展素材、任务及运行记录 |
| 凭据保护 | macOS Keychain，Rust 接入方式在 M0 确定 | 保护显式保存的 API 密钥；不把网页会话整体加密作为已实现能力 |
| 平台操作 | 豆包、京东独立 Adapter | 封装页面识别、能力检测、状态读取与具体操作 |
| 媒体检查 | FFprobe / FFmpeg，验证分发许可证及签名后固定构建 | 读取尺寸、时长、音轨，生成封面与缩略图 |
| 打包发布 | Tauri CLI，签名与 Apple 公证 | 产出 DMG；先提供手动更新与版本说明 |

Rust 后端负责数据库、会话、下载和任务调度；本地 React 界面通过窄接口命令调用。Capabilities 只授权本地管理窗口，不授权第三方页面；命令校验调用窗口与输入，限制导航及新窗口来源。若回退 Electron，远程页面禁用 Node 集成，启用上下文隔离和沙箱。

浏览器自动化优先采用已验证的元素语义与状态，集中封装在 Adapter。只对可信来源、预定义动作开放页面操作。Tauri 在 macOS 上不能直接依赖官方 tauri-driver 完成桌面 WebDriver 测试：本地前端可用浏览器测试，原生网页窗口先进行人工验证或独立 macOS UI 测试。若回退 Electron，再验证 Playwright 的 Electron 测试支持。

回退时保留 React 业务界面、平台无关数据结构、任务状态与验收清单；替换 Rust IPC、WebKit 会话实现、平台桥接和打包层。Electron 版本需通过同一组账号隔离、登录恢复、生成下载与上传验证，回退不等于省略验证。

官方 API 若确实开放且账号具备权限，应作为独立接入方式评估。网页版豆包与模型 API 是两种服务，不能假设账号额度、计费、视频能力或登录身份互通。M0 必须核实可接入范围，未确认的接口不进入承诺范围。

## 5. 数据与文件设计

| 实体 | 关键字段 |
| --- | --- |
| Account | ID、平台、名称、partition ID、会话状态、最近验证时间 |
| Product | ID、SKU、来源链接、标题、规格、图片、事实卖点、佣金来源及采集时间 |
| PromptVersion | 商品 ID、模板版本、输入快照、脚本、创建时间 |
| Asset | 商品 ID、脚本版本 ID、类型、路径、校验值、媒体参数、来源、人工审核状态 |
| Job / JobAttempt | 任务 ID、商品 ID、账号 ID、阶段、输入快照、状态、尝试次数、检查点、错误与时间 |
| Publication | 商品 ID、京东账号 ID、素材版本、提交状态、平台内容 ID、审核状态、核对时间 |
| MetricSnapshot | 账号、统计区间、时区、币种、指标口径、来源、金额与采集时间 |

金额以整数分保存，未知值与零分开。相对日期导入时必须补充对应日期；“近 7 天”和“近 30 天”等重叠指标不相加。

数据库和会话保存在应用 userData 目录；媒体使用用户选择的素材目录。数据库保存相对媒体路径并支持重定位。数据库迁移前建立备份，恢复时检查版本与文件完整性。普通备份不包含登录会话和密钥，恢复后重新登录。

## 6. 任务执行与恢复

任务状态：`queued → running → succeeded`；另设 `waiting_user`、`paused`、`failed`、`cancel_requested`、`cancelled` 和 `needs_reconcile`。任务阶段与任务状态分开存储，审核通过属于发布记录的状态。

- 默认全局并发为 1；同一账号互斥。验证资源占用和平台行为后，再允许不同账号并发。
- 每一步都有输入快照、完成条件、超时和结果记录。生成任务使用有截止时间的轮询，不用固定长等待判断完成。
- 网络超时等可恢复错误采用有限次数退避重试。验证码、登录失效、额度不足或页面结构变化进入人工接管或失败状态，不盲目循环。
- 生成请求和发布提交存在外部副作用。提交前落盘意图，响应不明确时进入 `needs_reconcile`，先核对远端记录再决定重试。
- 程序重启后，不把原 `running` 任务直接重新提交；先核对检查点与外部结果。
- 取消只保证停止后续本地动作；已发送的生成请求可能仍执行并计费，要保留远端状态供核对。
- 下载先写临时文件，完成并校验后原子重命名；失败不产生“已完成”素材。
- 删除账号时先处理关联任务，再按用户选择清理会话；保留历史记录的账号引用。

## 7. 开发里程碑

以下为一名熟悉桌面与网页自动化的开发者的初步工作量估算，不含等待账号权限、平台处理和签名证书的时间。按里程碑验收后调整排期。

| 里程碑 | 预计工作日 | 交付与通过条件 |
| --- | ---: | --- |
| M0 实际路径与技术验证 | 3–5 | 用授权测试账号走通豆包和京东网页路径，记录页面与失败状态；验证双账号隔离、生成/下载能力及 macOS 打包；输出可自动化清单与人工回退方案 |
| M1 桌面基础与账号 | 4–6 | Mac 应用可启动；账号管理、独立会话、设置、SQLite 迁移可用；两个账号重启后仍独立 |
| M2 商品与脚本 | 4–6 | CSV 导入、商品编辑、脚本模板、版本保存和候选标题可用；一个商品资料可完整恢复 |
| M3 任务与素材 | 6–9 | 持久队列、豆包适配、人工接管、下载和预览可用；生成结果能回到正确商品，异常不重复提交 |
| M4 京东发布辅助 | 4–6 | 打开正确账号、上传素材、填写内容与挂品，用户最终提交；结果未知时进入核对流程 |
| M5 macOS 内测与发布 | 4–6 | 完成关键流程验证、备份恢复、性能检查、签名公证和干净机器安装；交付 DMG 与使用说明 |

总估算约 25–38 个工作日。M0 若证明关键网页路径不稳定，第一阶段仍交付“商品 + 脚本 + 素材 + 人工接管 + 发布辅助”，相应自动化功能单独延期，不用模拟成功填补缺口。

## 8. 验证与首版验收

编写网页集成测试前，先实际探索授权账号的页面状态、交互与失败路径，保存经过脱敏的定位依据。本阶段测试对象为 macOS 与网页；后续若涉及 Android，先按项目 ARTEMIS 规则探索设备行为。

- **核心规则测试**：任务状态迁移、幂等与核对、账号锁、CSV 错误处理、金额口径及数据库升级回滚。
- **桌面集成验证**：账号隔离、IPC 参数与来源校验、下载中断、素材目录重定位、备份恢复。
- **真实平台验证**：显式开启、使用专用账号和少量任务，观察额度与提交副作用；CI 默认使用模拟页面，不自动消耗真实额度或发布内容。
- **恢复演练**：生成中断网、登录失效、应用退出重启、下载中断、提交后响应丢失；逐项确认数据可恢复且不会重复发布。
- **安装验证**：Apple Silicon 开发机和一台干净测试 Mac 安装签名公证后的 DMG，确认启动、登录、下载与卸载说明可用。

首版发布必须满足：

- [ ] 在支持的 Mac 上完成一次真实商品流程，人工环节在界面中明确可见。
- [ ] 连续处理 10 个测试任务，无串号、串商品、丢记录或重复提交；记录自动完成与人工接管比例。
- [ ] 两个账号能分别登录、切换与恢复，不互用 Cookie。
- [ ] 通过上述中断与未知结果恢复演练。
- [ ] 记录测试机配置、冷启动耗时和任务运行峰值内存；建议目标为可用工作台 5 秒内、单活动网页工作流峰值内存不超过 2 GB，M0 实测后固定预算。
- [ ] 日志和备份抽查不含明文密钥或可复用会话凭据。
- [ ] 正式安装包完成签名公证；未完成时仅标为开发预览。
- [ ] README 写清安装方式、支持系统、已实现功能、人工步骤和已知限制。

## 10. 第二与第三阶段

**第二阶段：扩大 macOS 自动化能力。** 根据内测数据优化失败率、生成成本与人工接管耗时；增加有权限的官方接口、可核对的审核状态同步、佣金报表导入、定时任务和 Intel 支持。自动最终提交仅在平台允许、用户明确启用且具备幂等与结果核对能力后加入。

**第三阶段：跨平台与商业化。** 在业务流程稳定后扩展 Windows，建立跨平台安装与回归测试；再根据真实需求开发团队协作、授权订阅和可选云服务。账号会话默认留在本机，云同步范围单独设计。

每阶段评估软件指标：单商品人工处理时长、生成完成率、人工接管率、素材返工率、发布辅助完成率和每条可用视频成本。订单和佣金单独统计，不将其作为软件稳定性指标。

## 11. 开始开发时的首批任务

1. 建立源码目录与开发命令，配置 TypeScript、桌面构建、测试和 CI；保留现有资料路径。
2. 完成 M0 验证记录 `docs/platform-validation.md`，记录支持能力、输入、完成条件、失败路径及人工回退。
3. 确认技术版本与支持系统，在 `docs/architecture.md` 固定进程边界、Adapter 接口和存储方案。
4. 先实现账号与单商品纵向流程，再扩展列表批量任务；阶段发布用实际验收记录更新本计划。
